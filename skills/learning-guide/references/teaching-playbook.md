## 模式选择

| 模式 | 触发信号 | 首要动作 | 完成证据 |
|---|---|---|---|
| 新学 | 学、讲解、从零开始 | 探测必要前置知识 | 能解释并完成一个基础应用 |
| 复习 | 复习、到期、忘了 | 不展示答案地检索 | 独立回忆并应用 |
| 测验 | 测验、检查效果、抽问 | 直接给一个代表性任务 | 在无提示条件下产生证据 |
| 查漏 | 不懂、混淆、为什么错 | 定位最小错误模型 | 能说出原模型与修正模型差异 |
| 项目实践 | 带我做、实战、实现 | 明确产物和验收标准 | 可运行产物、观测结果或报告 |

模式可以转换，但一次只维持一个主模式。例如测验暴露缺口后，临时切换到查漏；修正完成后回到测验验证。

## 会话设计

用三个元素定义最小学习单元：

- **目标**：本次只解决什么问题。
- **证据**：用户做出什么行为才说明学会。
- **停止条件**：达到证据、用户停止或发现更早的前置缺口。

示例：

```text
目标：理解 OceanBase 租户为什么不是 MySQL database。
证据：用户能解释资源隔离差异，并为两个业务判断是否应拆租户。
停止条件：解释和场景判断均成立，或发现用户尚不理解集群与资源单元。
```

时间预算不明确时，默认设计 10–15 分钟的最小单元，不生成覆盖整章的课程。

## 教学策略选择

| 学习障碍 | 优先策略 | 避免 |
|---|---|---|
| 缺少直觉 | 类比后立即给精确定义 | 只讲类比不收敛术语 |
| 概念混淆 | 正例与反例、比较表 | 重复原定义 |
| 会背不会用 | 场景题、预测结果 | 增加更多记忆题 |
| 实践失败 | 最小复现、观察—假设—验证 | 直接给完整答案覆盖现场 |
| 容易遗忘 | 无提示检索、交错复习 | 重读全文 |
| 表达含糊 | 费曼复述、追问因果 | 只判断“基本正确” |

苏格拉底追问每次只推进一个因果层级。连续追问没有新证据时，改用最小解释或示例，不让对话变成审问。

## 掌握度量

### 四级证据阶梯

1. **回忆**：说出定义、组成或步骤。
2. **解释**：说明为什么、各部分如何关联。
3. **应用**：完成熟悉情境中的选择、计算、代码或操作。
4. **迁移**：面对新条件、故障、反例或权衡仍能正确判断。

不要给没有量表支撑的 80%、90% 等百分比。需要摘要时使用：

- 尚未形成：无法稳定回忆核心模型；
- 初步形成：能回忆，解释仍依赖提示；
- 可应用：能独立解释并用于熟悉场景；
- 可迁移：能处理变化条件和边界。

### 技术主题的额外证据

- 概念：因果解释和反例。
- 编程：运行结果、测试或代码评审证据。
- 运维：命令输出、指标变化、故障定位链。
- 架构：约束、权衡和失败模式。
- 数据库：SQL 结果、执行计划、隔离或故障实验。

## 反馈与难度调整

反馈格式：

```text
判断：当前答案在哪个证据层级。
依据：指出一个具体正确点或错误点。
修正：只补当前阻塞所需内容。
下一步：提出一个主要动作。
```

调整规则：

- 连续两次独立正确：提高到应用或迁移，不继续同级重复。
- 核心模型错误：回退到更小前置概念。
- 只差术语：给术语提示，不重讲机制。
- 靠猜答对：更换表述或场景再次检索。
- 用户已能迁移：结束单元或进入真实项目，不无限加题。

## 闪卡质量

只创建能在脱离上下文后独立复习的卡片：

- 一张卡只测试一个核心关系。
- 正面应要求检索，不使用“是否理解……”之类提示。
- 背面简短，但包含判断答案所需的关键边界。
- 将易变的版本事实写入引用式复习项，避免复制后过时。
- 项目操作步骤优先建立笔记引用，而不是拆成大量孤立卡片。
- 创建前列出现有卡片或搜索同义问题，避免重复。

## 技术学习示例

### 新学

```text
目标：理解分区键如何影响查询。
探测：如果查询条件不包含分区键，你预计数据库要访问多少分区？
教学：根据回答补充“数据定位”和“分区裁剪”。
应用：给一张订单表和两种查询，让用户选分区键并说明代价。
迁移：加入热点写入条件，检查原选择是否仍成立。
```

### 复习

```text
先展示：为什么应用写超时后不能总是直接重试？
等待回答后判断：是否提到“服务端可能已提交”和“需要幂等或结果确认”。
再建议评分并提交；不在提问时展示评分标准答案。
```

### 项目实践

```text
产物：一条可执行 SQL 和对应执行计划。
预测：执行前先让用户预测是否发生分区裁剪。
观察：运行后比较预测和计划。
解释：要求用户说明差异来自统计信息、谓词还是分区设计。
```
