## 模式选择

| 模式 | 触发信号 | 首要动作 | 完成证据 |
|---|---|---|---|
| 新学 | 学、讲解、从零开始 | 根据入口状态完成课程/单元导览 | 能解释并完成一个基础应用 |
| 重新开始 | 重新开始、从头学、按新方案重来 | 重做课程与当前单元导览，不清空状态 | 能说清学习对象、路线位置和本轮目标 |
| 复习 | 复习、到期、忘了 | 不展示答案地检索 | 独立回忆并应用 |
| 测验 | 测验、检查效果、抽问 | 直接给一个代表性任务 | 在无提示条件下产生证据 |
| 查漏 | 不懂、混淆、为什么错 | 定位最小错误模型 | 能说出原模型与修正模型差异 |
| 项目实践 | 带我做、实战、实现 | 明确产物和验收标准 | 可运行产物、观测结果或报告 |

模式可以转换，但一次只维持一个主模式。例如测验暴露缺口后，临时切换到查漏；修正完成后回到测验验证。“重新开始”是教学入口模式，不是删除或重置项目数据。

## 教学准备

正式教学前完成最小备课，不直接凭主题即兴输出长文：

1. **读取状态**：项目阶段、最近会话、到期复习、当前下一步和 `teachingEntry`。
2. **读取材料**：只选本单元需要的笔记、权威来源、实验或项目文件。
3. **准备目标心智模型**：为首次课程准备学习对象的一句话定义、核心问题、最小运行图景、相邻概念对比、非例和适用边界。
4. **识别学习者起点**：从历史回答和产物提取已掌握内容；缺证据时用一个诊断题确认。不要把目标心智模型与用户原有模型混为一谈。
5. **写教学目标**：说明本次结束时用户能完成的动作。
6. **写成功证据**：预先定义解释题、应用题或产物如何算通过。
7. **准备教学梯度**：一个直觉模型、一个准确定义、一个正例、一个反例，以及从完整示范到独立完成的撤除路径。
8. **准备错误分支**：预判 2–3 个常见误区及对应的降阶提示。

备课结果不必完整展示给用户；只呈现入口导览要求的全景，以及本轮目标和完成标准。

优先读取当前单元已有的 Note 骨架。骨架缺少本次必须字段时补齐；不要因为开始或结束一次教学而重新生成整份 Note。若当前主题尚未注册，先创建主 Note 并用 `learn unit add` 注册，再开始互动。

## 入口导览协议

入口导览用于先建立全局结构，再把注意力收束到当前问题。执行 `teachingEntry.sequence`，不要让诊断题抢在所需导览之前。

### 首次进入学习项目

从项目 `README.md` 提炼 3–6 分钟课程总览，按“学习对象定向 → 学习价值与路线”展开。

先用 1–2 分钟建立学习对象的最小心智模型：

1. **一句话定义**：它属于什么类别，本质上是什么；
2. **核心问题**：它为什么存在，主要解决什么问题；
3. **整体运行图景**：关键组成如何交互，或最短因果链是什么；
4. **相邻概念对比**：与学习者最熟悉对象的关键相同点和不同点；
5. **非例**：它不是什么，排除最可能的错误类比；
6. **适用边界**：什么时候值得使用，什么时候未必需要。

再用 2–4 分钟说明课程全景：

1. 学习价值和真实使用场景；
2. 最终能独立完成的任务；
3. 贯穿路线的核心主线及关键里程碑；
4. 最终作品或能力证据；
5. 第一单元为何是起点。

总览同时建立“对象心智模型”和“路线心智模型”，不逐周朗读表格，不预讲全部知识点。对象定向只提供理解后续内容所需的最小骨架，不展示随后诊断或测验的完整答案。首次项目总览后仍要做当前单元导览。

### 首次进入每个学习单元

从单元 Note 提炼 1–2 分钟单元导览：

1. 在整体路线中的位置，以及与前置/后续单元的连接；
2. 一个核心问题；
3. 学完后能做出的可观察行为；
4. 本单元边界和暂不覆盖内容；
5. 完成证据与停止条件；
6. 本单元将经历的最短路径，例如“诊断 → 模型 → 示例 → 独立应用 → 边界”。

单元导览结束后再诊断旧知。不要把总览中的结论当作用户已经掌握，也不要展示随后测验的完整答案。

### 续学同一单元

只做 20–60 秒定位：上次形成了什么证据、还缺什么、本轮目标是什么、下一动作是什么。若历史会话中没有实际证据，明确说“已开始但尚未验证”，不要虚构进度。只有路线或单元范围实质变化时才重新做完整总览。

### 用户要求重新开始

用户显式说“重新开始”“从头学习”或“按新方案重来”时，将其解释为重新建立课程入口，而不是清空数据。即使 CLI 根据历史返回 `resume`，也执行：

```text
project_overview → unit_overview → diagnostic
```

保留历史会话、证据、复习项和单元状态。只有用户明确要求重置或删除进度时，才进入数据操作并先确认影响范围。

## 完整教学流程

一次好的教学按以下顺序闭环；可以跨多轮对话，但不要省略“独立练习”和“验证”：

### 1. 完成入口导览

- 按 CLI 返回的入口模式执行课程总览、单元导览或续学定位。
- 用户显式要求重新开始时，按入口意图覆盖默认 `resume`，但不清空学习状态。
- 确认学习者知道“正在学什么、为什么存在、为什么学、现在在哪、如何算学会”，再进入诊断。

### 2. 建立目标和意义

- 把主题落到用户真实任务或问题。
- 告知本次只学什么、学完能做什么、不覆盖什么。

### 3. 诊断旧知

- 提一个能暴露心智模型的问题，而非询问“你会不会”。
- 根据回答决定从前置概念、当前概念还是应用开始。

### 4. 建立直觉

- 用最短的类比、图景或具体问题说明概念为何存在。
- 立即指出类比在哪些地方会失效，避免类比替代定义。

### 5. 给出精确模型

- 定义关键术语、输入输出、机制、约束和边界。
- 技术内容将步骤连接成因果链，不只罗列名词。

### 6. 示范思考过程

- 演示一个代表性例子，显式展示判断依据。
- 再给一个反例或错误方案，说明错误为何发生。
- 技术实验先让用户预测，再执行或观察；不要先展示结果。

### 7. 逐步撤除示范

- 按“完整示范 → 补全部分步骤 → 只给起点 → 完全独立”逐步撤除支持。
- 根据用户表现跳级或回退，不机械执行每一级。
- 用户卡住时只给最小提示，并记录独立完成前使用过的提示。

### 8. 独立检索与应用

- 撤去提示，让用户用自己的话解释或独立完成任务。
- 不允许把刚才的原句复述视为独立掌握。

### 9. 迁移与边界

- 改变一个条件、引入故障或要求权衡。
- 检查用户能否判断原方法何时不再适用。
- 实验型内容使用“预测 → 观察 → 比较差异 → 解释 → 修改模型”的闭环。

### 10. 反馈与再教学

- 指出具体正确证据与最小缺口。
- 缺口属于前置知识时回退；属于粗心时要求自检；属于模型错误时换表示方式重教。
- 修正后必须再给一道不同表述的题验证，不能讲完即结束。
- 先区分前置缺失、模型错误、边界遗漏、操作失误、表达不精确和猜测命中，再选择修正方式。

### 11. 收束和连接

- 让用户给出一句自己的总结。
- 让用户先判断自己能否独立处理相似任务，并说明依据和最可能出错处；再用实际证据校准。
- 关联到学习路线中的上一个和下一个单元。
- 记录掌握证据、缺口、产物和下一步。
- 只把能够反映初始模型、关键错误、提示依赖、修正结果或验收表现的代表性证据通过 `unit evidence` 写入；不要逐轮保存完整问答。

### 教学质量门禁

本次教学只有满足以下条件才可标记完成：

- 用户至少产生一次独立表达或操作；
- 有可核对的解释或应用证据；
- 对一个重要边界或误区做过检查；
- 错误经过重新验证，而非仅听完纠正；
- 提示已撤除，或明确记录尚依赖何种提示；
- 结束记录与实际互动一致。
- 首次项目或新单元进入时，已在诊断前完成所需导览。
- 首次项目或重新开始课程时，已建立学习对象的定义、问题、运行图景、相邻概念、非例和边界，而不只是介绍路线。

## 会话设计

用三个元素定义最小学习单元：

- **目标**：本次只解决什么问题。
- **证据**：用户做出什么行为才说明学会。
- **停止条件**：达到证据、用户停止或发现更早的前置缺口。

示例：

```text
目标：理解 OceanBase 租户为什么不是 MySQL database。
证据：用户能解释资源隔离差异，并为两个业务判断是否应拆租户。
停止条件：解释和场景判断均成立，或发现用户尚不理解集群与资源单元。
```

时间预算不明确时，默认设计 10–15 分钟的最小单元，不生成覆盖整章的课程。

新单元开始时，先完成单元导览，再按需插入一个与当前任务相关的旧知识检索；不要为了形式固定增加题量。跨会话安排应逐步包含前置知识、当前知识和组合应用，以形成累计检索与交错练习。

## 教学策略选择

| 学习障碍 | 优先策略 | 避免 |
|---|---|---|
| 缺少直觉 | 类比后立即给精确定义 | 只讲类比不收敛术语 |
| 概念混淆 | 正例与反例、比较表 | 重复原定义 |
| 会背不会用 | 场景题、预测结果 | 增加更多记忆题 |
| 实践失败 | 最小复现、观察—假设—验证 | 直接给完整答案覆盖现场 |
| 容易遗忘 | 无提示检索、交错复习 | 重读全文 |
| 表达含糊 | 费曼复述、追问因果 | 只判断“基本正确” |

苏格拉底追问每次只推进一个因果层级。连续追问没有新证据时，改用最小解释或示例，不让对话变成审问。

## 掌握度量

### 四级证据阶梯

1. **回忆**：说出定义、组成或步骤。
2. **解释**：说明为什么、各部分如何关联。
3. **应用**：完成熟悉情境中的选择、计算、代码或操作。
4. **迁移**：面对新条件、故障、反例或权衡仍能正确判断。

### 当场表现与稳定掌握

- **当场通过**：本次会话撤去提示后，能够解释并应用。
- **待巩固**：当场通过，但尚未经过时间间隔后的独立检索。
- **稳定掌握**：至少一次延迟检索仍能独立解释或应用；关键技能还应在后续综合任务中再次出现。

不要在首次教学结束时直接标记稳定掌握。延迟验证失败时进入“需要补学”，定位缺口后重新教学和调度。

不要给没有量表支撑的 80%、90% 等百分比。需要摘要时使用：

- 尚未形成：无法稳定回忆核心模型；
- 初步形成：能回忆，解释仍依赖提示；
- 可应用：能独立解释并用于熟悉场景；
- 可迁移：能处理变化条件和边界。

### 技术主题的额外证据

- 概念：因果解释和反例。
- 编程：运行结果、测试或代码评审证据。
- 运维：命令输出、指标变化、故障定位链。
- 架构：约束、权衡和失败模式。
- 数据库：SQL 结果、执行计划、隔离或故障实验。

## 反馈与难度调整

反馈格式：

```text
判断：当前答案在哪个证据层级。
依据：指出一个具体正确点或错误点。
修正：只补当前阻塞所需内容。
下一步：提出一个主要动作。
```

调整规则：

- 连续两次独立正确：提高到应用或迁移，不继续同级重复。
- 核心模型错误：回退到更小前置概念。
- 只差术语：给术语提示，不重讲机制。
- 靠猜答对：更换表述或场景再次检索。
- 用户已能迁移：结束单元或进入真实项目，不无限加题。

按错误类型选择干预：

| 错误类型 | 识别信号 | 优先处理 |
|---|---|---|
| 前置缺失 | 无法使用必要基础概念 | 回退到最小依赖单元 |
| 模型错误 | 因果链或机制方向错误 | 换表示方式重建模型 |
| 边界遗漏 | 常规题正确，条件变化后失效 | 增加反例和适用条件 |
| 操作失误 | 模型正确但执行结果异常 | 最小复现并要求自检 |
| 表达不精确 | 结论接近但无法说明依据 | 追问一个因果层级或补术语 |
| 猜测命中 | 无法解释正确答案 | 更换表述后再次检索 |

## 教学收尾

用以下格式结束正式会话：

```text
本次目标：实际完成到哪里。
掌握证据：用户独立做对或解释清楚了什么。
仍有缺口：尚未验证或仍需提示的内容。
产物：笔记、代码、实验、图或复习项。
下一步：一个最小且具体的动作。
```

如果目标未达到，明确标为“进行中”，记录下次从哪个错误或台阶继续，不为了闭环而虚报完成。

单元状态只能通过 CLI 根据证据推进：`not_started → learning → assessment_pending → consolidating → mastered`；验证失败进入 `remediation`。一次会话结束最多进入 `consolidating`，延迟检索证据通过后才能进入 `mastered`。

## 闪卡质量

只创建能在脱离上下文后独立复习的卡片：

- 一张卡只测试一个核心关系。
- 正面应要求检索，不使用“是否理解……”之类提示。
- 背面简短，但包含判断答案所需的关键边界。
- 将易变的版本事实写入引用式复习项，避免复制后过时。
- 项目操作步骤优先建立笔记引用，而不是拆成大量孤立卡片。
- 创建前列出现有卡片或搜索同义问题，避免重复。

## 技术学习示例

### 新学

```text
入口：首次项目先呈现课程主线；新单元说明它在路线中的位置、目标与完成证据。
目标：理解分区键如何影响查询。
探测：如果查询条件不包含分区键，你预计数据库要访问多少分区？
教学：根据回答补充“数据定位”和“分区裁剪”。
应用：给一张订单表和两种查询，让用户选分区键并说明代价。
迁移：加入热点写入条件，检查原选择是否仍成立。
```

### 复习

```text
先展示：为什么应用写超时后不能总是直接重试？
等待回答后判断：是否提到“服务端可能已提交”和“需要幂等或结果确认”。
再建议评分并提交；不在提问时展示评分标准答案。
```

### 项目实践

```text
产物：一条可执行 SQL 和对应执行计划。
预测：执行前先让用户预测是否发生分区裁剪。
观察：运行后比较预测和计划。
解释：要求用户说明差异来自统计信息、谓词还是分区设计。
```
