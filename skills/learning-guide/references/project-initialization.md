## 完成定义

学习项目准备完成必须同时满足：

1. 学习目标描述为可执行能力，而非“了解某主题”。
2. 已识别前置知识、范围边界和时间约束。
3. 学习内容按依赖关系分阶段，不只是罗列目录。
4. 每阶段都有学习材料、主动练习、可观察产出和验收标准。
5. `README.md` 已建立学习对象的最小心智模型，并能直接支持首次课程总览；每个核心单元 Note 能直接支持首次单元导览，第一个学习单元可以立即开始。
6. 项目已由 CLI 注册，核心文件不存在占位符。
7. 核心单元已通过 CLI 注册，依赖关系、Note 路径和项目路线一致。
8. 至少一个高价值内容已进入复习体系，或明确说明为何暂不创建。

只有目录创建成功不能称为初始化完成。

## 输入诊断

### 信息来源顺序

按以下顺序获得初始化信息，不重复询问已经明确的内容：

1. 当前对话中用户已经说明的目标、背景和限制；
2. 用户指定的现有项目、材料和可读状态；
3. 能安全采用的默认假设；
4. 仍会实质改变路线的缺口。

### 核心输入

| 维度 | 需要明确的内容 | 影响 |
|---|---|---|
| 目标能力 | 最终要在什么条件下独立完成什么任务 | 决定终点、产物和验收 |
| 使用场景 | 工作、项目、考试、研究或兴趣 | 决定深度、题型和取舍 |
| 时间约束 | 期限、每周大致投入；只有必要时确认单次时长 | 决定路线规模和颗粒度 |

### 条件输入

以下信息优先推断，只在会改变设计时询问：

| 维度 | 处理方式 |
|---|---|
| 当前基础 | 不要求用户自报初级、中级或高级；从已有产物推断，并在首个学习单元用诊断任务验证 |
| 环境限制 | 只有安装、硬件、权限、成本或实验可行性受影响时确认 |
| 指定材料 | 用户已提供书籍、课程或文档时确认是否必须作为主线，否则按质量和目标筛选 |
| 学习偏好 | 默认不询问；先采用短讲解、主动练习和实践，根据实际表现调整 |

### 最小提问协议

1. 先列出已知事实、可接受假设和真正阻塞路线的缺口。
2. 没有阻塞缺口时直接初始化，并在 README 的“起点与假设”中记录假设。
3. 有阻塞缺口时只询问会改变终点、路线规模或实践可行性的内容，一次集中提出，最多三个短问题。
4. 用户暂未回答且可以安全默认时，明确默认值并继续；无法安全默认时将项目标为“待确认”，先完成不依赖该决定的部分。
5. 不把初始化问卷变成教学诊断。知识基础、错误模型和提示需求在首个学习单元通过实际任务验证。

推荐问法：

```text
为了确定学习终点和路线规模，我只确认三点：
1. 学完后最希望独立完成什么任务？
2. 主要用于工作、项目、考试还是系统理解？
3. 是否有期限或每周时间预算？
其余信息我会根据现有背景作出假设，并在第一节通过诊断任务调整。
```

## 项目设计

### 1. 建立学习对象的最小心智模型

在设计路线前先回答：

```text
一句话定义：它属于什么类别，本质上是什么。
核心问题：它为什么存在，主要解决什么问题。
整体运行图景：关键组成如何交互，或最短因果链是什么。
相邻概念对比：它与学习者最熟悉对象有什么相同和不同。
非例：它不是什么，最容易被误认为何物。
适用边界：什么时候值得使用，什么时候未必需要。
```

该模型服务于首次认知定向，不是完整教材。相邻概念优先从用户已知背景推断；无法确认时使用领域内最常见参照并明确它只是参照，不为选择类比额外增加问卷。版本敏感内容注明项目基准版本，定义和关键边界优先核对权威来源。

### 2. 定义目标和边界

使用以下格式：

```text
目标能力：能够在什么条件下，完成什么任务，达到什么质量。
适用场景：为什么学习、在哪里使用。
不包含：本阶段明确不学什么。
完成证据：作品、运行结果、解释、测验或真实任务。
```

### 3. 建立知识依赖图

先列能力，再倒推知识：

```text
最终任务
├─ 必需概念
├─ 必需操作
├─ 必需诊断能力
└─ 必需权衡能力
```

对每个单元标记：先修、输入材料、练习、产出和常见失败。按依赖排序，不能只照书籍目录复制。

### 4. 划分里程碑

每个阶段控制在一个可验收能力跃迁：

| 字段 | 要求 |
|---|---|
| 阶段目标 | 动词开头，可观察 |
| 核心问题 | 2–5 个必须回答的问题 |
| 学习内容 | 只列支撑问题所需内容 |
| 主动练习 | 回忆、解释、操作、分析或设计 |
| 阶段产出 | 笔记、代码、实验报告、图或讲解 |
| 验收标准 | 正确性、独立性、边界和质量门槛 |
| 预计投入 | 阅读、实践和复习分别估算 |

### 5. 设计首个学习单元

首个单元应在一次会话内完成，包含：

- 一个面向学习者的单元导览：路线位置、前置连接、范围和完成证据；
- 一个明确问题；
- 必需的最少材料；
- 一个探测题；
- 一个应用任务；
- 一个完成标准；
- 下一次复习入口。

### 6. 设计可演进的内容骨架

初始化不是只创建第一个章节，也不是预写完整教材。根据知识依赖图，为核心路线一次性准备可导航、可继续教学的骨架：

- `README.md` 先提供学习对象定向和可在 3–6 分钟呈现的课程总览，再列出全部阶段、核心问题、依赖、产出与验收标准；
- `knowledge/` 建立覆盖核心路线的知识地图，标明概念关系、边界与对应学习单元；
- `notes/` 为确定要学习的核心单元建立主题化 Note 骨架，至少包含单元导览、问题、目标、前置、材料、诊断、练习和验收；
- `projects/` 建立路线所需的实验与综合实践入口，先写约束和验收，不伪造结果；
- 所有未实际学习的内容标记为“待学习”或“骨架”，不得填入用户总结、掌握证据、学习时长或完成状态。

骨架颗粒度以一个 Note 能在一次或少量连续会话中形成独立掌握证据为准。主题仍不确定时只在知识地图保留问题和依赖，不批量创建空文件。

## 创建与注册

### 新项目

1. 用 `learn new <topic> [--path <path>] --json` 创建受管项目。
2. 读取返回的项目路径和名称，不猜测。
3. 检查生成的目录和 CLI 状态：`learn status <project> --json`。
4. 创建 Note 骨架后，按依赖顺序运行 `learn unit add` 注册核心单元。

### 已有目录

1. 先确认目录确实是用户指定的学习项目。
2. 检查已有 README、进度、笔记、资源和项目内容。
3. 用 `learn project import --path <dir> [--name <name>] [--topic <topic>] --json` 注册。
4. 导入不得覆盖现有知识文件；出现冲突时先报告。

## 内容落地

CLI 模板生成后，必须进行主题化改写。以下顶层结构是与 CLI 的数据契约，不得另造同义的平行目录或文件：

```text
README.md
progress.md
learning-units.json
notes/
knowledge/
flashcards/deck.json
projects/
resources/
reviews/review-index.json
reviews/review-history.json
reviews/session-history.json
```

内容映射固定如下：

| 内容 | 固定位置 | 不要另建 |
|---|---|---|
| 总目标、路线、阶段和验收 | `README.md` | `learning-plan.md`、`roadmap.md` |
| 状态、实际时长、阻塞和下一步 | `progress.md` | `status.md`、`study-log.md` |
| 单次学习笔记 | `notes/` | `lessons/` |
| 单元、依赖与能力证据 | 通过 CLI 写入 `learning-units.json` | 手工状态表、第二套证据索引 |
| 可复用概念与机制 | `knowledge/` | `concepts/` |
| 实验、代码、报告与能力证据 | `projects/` | `labs/`、`evidence/` |
| 书籍、文档、课程与来源说明 | `resources/` | 根目录 `references.md` |
| 内联闪卡 | 通过 CLI 写入 `flashcards/deck.json` | 手工维护 `flashcards.md` |
| 调度、复习与会话历史 | 通过 CLI 写入 `reviews/*.json` | `review-log.md` |

至少完成：

- 入口文件：学习对象的一句话定义、核心问题、整体运行图景、相邻概念、非例和适用边界，以及课程价值、最终能力、核心主线、最终证据、假设、路线、阶段验收和第一单元，能够直接支撑首次开课总览。
- 进度文件：当前状态、下一步、阻塞、里程碑表；不伪造学习时长。
- 资源文件：资源用途、版本、适用阶段和选择理由。
- 实践入口：至少一个与最终能力一致的任务及验收标准。
- 笔记目录：为核心路线建立有教学内容的 Note 骨架；每个 Note 的单元导览说明路线位置、前置连接、核心问题、目标、范围、完成证据和学习路径。不要只建立首个主题，也不要预生成只有标题的空笔记。
- 单元索引：每个核心 Note 对应一个稳定单元 ID；按依赖顺序调用 `learn unit add`，不得手工编辑 `learning-units.json`。
- 项目目录：将实验、代码和验收证据放在同一个任务目录中，例如 `projects/java-connect/`，不要拆成平行的 `labs/` 与 `evidence/`。

## 初始化复习系统

项目创建时不要批量生成未经学习的闪卡。只允许：

- 为已确认的前置知识创建诊断性复习项；
- 将高质量路线或首个项目作为引用式复习入口；
- 在实际学习后创建基于用户错误和关键边界的闪卡。

通过 `learn flashcard add-note/add-knowledge/add-project` 注册引用内容。CLI 成功返回前，不声称已排期。

## Note 生命周期

一个知识单元默认维护一个主 Note，不在每次学习后重新生成：

```text
not_started → learning → assessment_pending → consolidating → mastered
                    └───────────────────────→ remediation
```

- **初始化**：写入单元导览、问题、目标、前置、精选材料、诊断题、教学梯度、练习和验收量表。
- **学习中**：只追加能够反映关键错误、提示依赖、实验观察或验收结果的代表性证据；完整对话不写入 Note。
- **收尾**：追加用户自己的总结、掌握证据、仍有缺口、产物引用和唯一下一步。
- **复习**：通过延迟检索判断能否从 `consolidating` 进入 `mastered`，失败则进入 `remediation`；追加遗忘点、迁移证据和模型修正，稳定、可复用内容再提炼到 `knowledge/`。

保留精选认知变化证据，不静默覆盖历史证据。只有单元过大需要拆分、路线范围实质变化或原 Note 损坏时才重构；重构时保留来源链接或迁移记录。

## 验收清单

完成前逐项检查：

- [ ] 项目名、路径、主题和 CLI 索引一致。
- [ ] `learning-units.json` 由 CLI 创建，单元 ID、依赖和 Note 路径与 README 路线一致。
- [ ] 顶层结构遵循 CLI 契约，没有同义的平行计划、实验、证据或复习目录。
- [ ] 目标是可观察能力，完成证据明确。
- [ ] README 先建立学习对象的最小心智模型，再生成首次课程总览；每个核心 Note 都有可直接呈现的单元导览。
- [ ] 已知事实、初始化假设和待确认项已记录；没有重复询问已有信息。
- [ ] 前置知识和不学范围明确。
- [ ] 路线按依赖排序，每阶段有产出与验收。
- [ ] 核心路线已有知识地图和可执行的 Note 骨架，不只有第一个章节或空标题。
- [ ] 未学习骨架与已掌握内容明确区分，Note 生命周期和增量记录位置清楚。
- [ ] 时间预算现实，阅读、实践、复习都有占比。
- [ ] 资源包含版本与用途，没有无筛选链接堆积。
- [ ] 第一个学习单元可立即执行。
- [ ] 至少一个实践项目与最终目标一致。
- [ ] 所有模板占位符已删除。
- [ ] CLI `status` 能读取项目；写入结果均已核对。
- [ ] 新增文件通过仓库自身检查。

任一关键项不满足时，说明项目处于“草稿”或“待准备”，不要宣称完整。
