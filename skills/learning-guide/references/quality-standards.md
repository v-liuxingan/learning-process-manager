## 通用质量门禁

每项学习内容都必须满足：

- **目标相关**：直接支撑某个目标能力或已知缺口。
- **事实可靠**：版本敏感内容注明版本；外部结论优先权威来源。
- **可操作**：用户知道下一步做什么，而非只得到描述。
- **可验证**：有答案、运行结果、评价量表或验收标准。
- **边界明确**：说明适用条件、限制或常见误区。
- **颗粒适当**：一次会话、一次复习或一个里程碑能够处理。
- **可追踪**：能关联到来源、项目目标、学习记录或复习项。
- **结构一致**：使用 CLI 标准目录；扩展内容放入最接近的标准目录，不创建第二套计划、实验、证据或复习体系。

## 学习路线

### 必须字段

| 字段 | 质量要求 |
|---|---|
| 目标能力 | 使用“能够……”描述真实行为 |
| 起点假设 | 前置知识、环境和时间预算 |
| 阶段顺序 | 体现依赖关系和难度递进 |
| 核心问题 | 每阶段 2–5 个驱动问题 |
| 主动练习 | 不能只有阅读或观看 |
| 阶段产出 | 用户实际生成的证据 |
| 验收标准 | 包含正确性、独立性和边界 |
| 时间估算 | 区分学习、实践和复习 |
| 课程总览 | 能在首次开课时简要说明价值、最终能力、核心主线、最终证据和第一单元 |

### 质量要求

- 阶段数量服务于目标，不强制套用 Novice 到 Master 五级。
- 路线必须能解释“为什么这个单元在前、那个单元在后”。
- 每阶段至少一次无提示检索和一次应用。
- 目标或时间变化时允许重排，并记录理由。

## 学习资源

每个资源记录：

```text
标题与链接/位置
来源与版本/发布日期
用途：解决哪个核心问题
适用阶段与建议章节
使用方式：精读、查阅、实验或选修
限制：过时风险、环境要求、偏见或缺失内容
```

拒绝没有用途说明的长链接列表。关键结论需回到官方文档、标准、论文、源码或一手材料核对。

## 笔记与知识节点

### 最低结构

```markdown
# 主题

## 单元导览
## 要解决的问题
## 一句话结论
## 核心机制或步骤
## 示例与反例
## 适用边界和常见错误
## 主动练习
## 自己的总结
## 来源与相关知识
```

康奈尔格式可将这些内容分布在线索栏、笔记栏和总结栏，但栏目齐全不代表质量合格。

### 质量要求

- 笔记回答问题，不逐段抄资料。
- 事实、实验观察和个人推断明确区分。
- 至少包含一个由用户生成的解释、例子或决策。
- 技术笔记的命令和代码应可运行，或标明伪代码。
- 版本敏感行为注明实验环境。
- 一个笔记聚焦一个可独立检索的主题。
- 每个核心学习单元在正文前部包含学习者可直接理解的导览：路线位置、前置连接、核心问题、学完能做、范围、完成证据和学习路径。
- 初始化骨架必须已经包含真实核心问题、练习和验收量表，不能只是标题模板；尚未学习的用户回答和掌握证据保持为空并明确标记状态。
- 同一知识单元默认维护一个主 Note；只保留能证明初始模型、关键错误、提示依赖、修正或验收结果的代表性片段，不保存完整对话。
- 学习结束不得重新生成整份 Note 覆盖过程证据；需要拆分或重构时保留迁移关系。
- 同一会话中的正确表现最多标记“待巩固”；只有延迟检索仍能独立解释或应用，才标记“稳定掌握”。
- 主 Note 的快速回顾区只放已核对模型；错误回答只出现在证据区，并明确标记为初始模型或错误，不得与事实结论混排。

## 练习与测验

每道题必须包含：

- 目的：检验回忆、解释、应用还是迁移；
- 前置条件和题目输入；
- 明确任务，避免多个考点混为一题；
- 参考答案或评分量表；
- 常见错误及其暴露的知识缺口；
- 下一步：答错如何降阶，答对如何加深。
- 提示记录：使用过哪些提示，最终是否独立完成。

题组应覆盖：

1. 无提示回忆；
2. 因果解释；
3. 熟悉场景应用；
4. 条件变化或反例。

不使用“你理解了吗”作为测验。不把选择题正确直接判定为会应用。

## 实践项目

### 必须字段

```text
业务/问题背景
目标产物
输入、约束和环境
里程碑
验收测试或评价量表
观察指标
失败场景
复盘问题
```

### 质量要求

- 项目必须逼迫用户调用目标能力，而非照抄教程。
- 至少保留一个需要选择与解释的设计决策。
- 验收标准可重复执行；技术项目优先使用测试、命令输出或指标。
- 难度允许裁剪，但裁剪后仍保持最小闭环。
- 项目结束必须比较预期与实际，并记录一个改进项。

## 闪卡与复习项

### 闪卡格式

```text
正面：一个无需额外上下文即可回答的问题
背面：最小充分答案 + 必要边界
标签：主题、阶段或错误类型
来源：可选的笔记引用
```

### 质量要求

- 一卡一考点；不能把整章摘要放在背面。
- 正面要求主动检索，不给出答案线索。
- 优先记录高频、易混淆、曾答错或具有决策价值的内容。
- 易变内容使用引用式复习项，避免复制后过时。
- 创建前检查语义重复。
- 未学习或未核对的内容不批量制卡。

## 会话记录与进度

会话记录必须基于实际发生内容：

```text
日期与真实时长
本次目标
完成的学习动作
掌握证据
暴露的缺口
产生的产物/引用
唯一下一步
```

进度更新要求：

- 文件创建、阅读时长与能力掌握分别记录，不相互替代。
- 阶段提升必须引用持续证据，不凭单次自评。
- 区分当场通过、待巩固和稳定掌握；记录自我判断与实际证据的明显偏差。
- 未完成项和阻塞项保留，不用模糊措辞隐藏。
- CLI 写入失败时记录待补写内容，不制造成功状态。

## 拒收条件

出现任一情况时，产物不得标记为完成：

- 存在模板占位符、空标题或虚构时长。
- 只有资源和讲解，没有主动练习。
- 没有答案、评分标准或可验证结果。
- 引用版本与实验版本明显不匹配且未说明。
- 笔记主要是复制原文，无法看出学习者理解。
- 项目只有步骤，没有决策、故障或验收。
- 闪卡过长、重复、依赖缺失上下文或答案含糊。
- 仅因用户说“懂了”就更新为掌握。
- 首次课程或新单元只能从文件名和目录猜测方向，无法在诊断前给出课程/单元导览。
