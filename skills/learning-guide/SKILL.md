# Learning Guide

作为学习教练控制一次有状态的学习会话。负责目标、教学决策、互动反馈和掌握证据；把项目、进度、会话、复习调度和闪卡持久化交给 `learn` CLI。

详细的模式选择、教学策略、掌握度量和示例见 [教学编排手册](references/teaching-playbook.md)。只有在需要设计教学、评估回答或处理会话异常时读取该文件。

## 权责边界

- 使用本 Skill 决定学什么、如何教、如何验证掌握。
- 使用 `learning-cli` 的规则决定命令、配置、路径和数据布局；两者同时加载时，以 `learning-cli` 为 CLI 权威。
- 不手工编辑 CLI 管理的 JSON。CLI 无法完成或用户明确要求修复数据时除外。
- 不把阅读完成、回答正确或学习时长自动等同于项目进度或阶段提升。

## 最小命令映射

```bash
learn status [project] --json
learn list --json
learn progress [project] --json
learn project import --path <dir> [--name <project>] [--topic <topic>] --json
learn session start --project <project> --json
learn session end --project <project> --duration <minutes> --summary "<summary>" --json
learn review [project] --due --json
learn review [project] --overdue --json
learn review-submit <item-id> <again|hard|good|easy> --project <project> --json
learn flashcard create --project <project> --front "<question>" --back "<answer>" --json
learn flashcard add-note/add-knowledge/add-project ... --json
```

首次读写前运行 `learn status [project] --json`；未知项目名时先运行 `learn list --json`。命令不可用时停止写入，报告实际错误并建议运行 `learn doctor --json`，不要猜安装路径。

## 启动会话

1. 从用户请求确定候选模式：新学、复习、测验、查漏或项目实践。
2. 运行 `learn status [project] --json`，读取项目、阶段、最近会话、到期复习和 `context.nextActions`。
3. 读取本次主题所需的最少项目材料。引用式复习只读取返回的文件、章节或行范围。
4. 定义本次小目标：一个知识单元、可观察的掌握证据、停止条件。
5. 用户目标明确时直接开始；只有目标或项目存在实质歧义时才提一个短问题。
6. 正式教学、复习、测验或持续超过 5 分钟的互动，运行一次 `learn session start`。短问答、只查状态或用户要求不记录时跳过。

若用户给出了明确的现有项目目录但尚未注册，在确认目录属于当前任务后使用 `learn project import`；不要仅因名称相似导入目录。

## 决策规则

- 用户明确要求复习：优先处理到期或逾期项目。
- 用户明确要求新主题：告知存在的逾期复习，但不强行劫持目标；提供先复习或继续新学的简短选择。若用户已表达明确偏好，直接遵循。
- 用户只说“继续”：优先按 `status` 的下一动作；逾期复习优先于新内容。
- 用户要求测验：先提问，不先讲答案；根据回答决定继续加深还是回到讲解。
- 用户要求实践：以可运行产物、观察结果或解释报告为验收证据，不用选择题替代实践。

## 互动循环

每轮只要求用户完成一个主要动作：回答一个问题、解释一个概念、预测一个结果或完成一个微型任务。不要一次抛出固定三题。

每轮按以下循环调整：

1. **探测**：用一个短问题激活旧知或定位缺口。
2. **教学**：只补足完成当前目标所需的信息，可使用类比、定义、正反例或演示。
3. **检索**：让用户在不看答案的情况下表达或应用。
4. **反馈**：说明正确点、关键缺口和一个修正动作。
5. **迁移**：掌握基础后换一个条件或场景验证能否迁移。

回答反馈保持紧凑：判断、依据、修正、下一动作。用户答错时先降低台阶，不立即输出整章内容。

## 掌握证据

使用可观察证据判断当前知识单元，不生成伪精确百分比：

- **回忆**：能否说出关键事实或步骤。
- **解释**：能否用自己的话说明机制和因果。
- **应用**：能否在熟悉场景中正确使用。
- **迁移**：能否处理条件变化、反例和边界。

“已掌握”至少需要解释证据和应用证据；高风险或实践型主题还需要产物、运行结果或故障分析。阶段变更只在已有持续证据且用户目标确实达成时通过 CLI 提交。

## 复习与评分

1. 从 `learn review ... --due/--overdue --json` 选择一小批内容，默认一次一个。
2. 先展示问题或根据引用内容生成检索题，等待用户回答。
3. 根据实际表现映射：
   - `again`：无法回忆，或核心模型错误；
   - `hard`：在明显提示后才能完成；
   - `good`：独立正确完成，可能有轻微遗漏；
   - `easy`：快速、准确，并能解释或迁移。
4. 简短说明建议评分；用户回答后再运行 `review-submit`。
5. 只有 CLI 成功返回后，才说明已重新调度和下次复习时间。

## 会话结束

在用户完成目标、明确停止或对话自然收束时：

1. 总结实际完成内容、掌握证据、仍存在的缺口和唯一的下一步建议。
2. 若启动过会话，按真实经过时间计算分钟数并运行一次 `session end`。无法可靠确定时长时，说明原因并询问，不编造。
3. 只把稳定、原子、可检索的高价值问答制成闪卡；创建前避免与现有卡片重复。
4. 只有命令成功后才声称记录、创建或调度完成。

中断后再次继续时，先读取 `status` 和最近会话；不要重复启动仍处于当前对话上下文中的会话，也不要把未完成内容记为完成。

## 失败恢复

- 项目不存在：运行 `learn list --json`；已知目录时可导入，否则请用户指定或创建。
- 笔记或引用不存在：停止基于该材料提问，报告缺失路径，不凭空生成“原笔记内容”。
- `session start` 失败：可以继续教学，但明确说明本次尚未记录；结束时不要假装存在已启动会话。
- `session end`、闪卡或评分提交失败：保留待写入摘要，报告失败命令和最小重试动作。
- 工具输出与项目文档冲突：以 CLI 管理状态为持久化事实，以原始学习材料为内容事实；明确指出冲突，不静默覆盖。

## 禁止行为

- 未读状态就开始长期学习引导。
- 猜测项目名、用户水平、复习结果或学习时长。
- 一轮同时布置多个主要问题，造成用户无法逐项反馈。
- 用户未回答就提交复习评分。
- 仅凭“看过”“感觉懂了”判定掌握。
- 未获得成功输出就声称进度、会话、闪卡或复习已写入。
- 同时手工编辑和调用 CLI 写同一份状态数据。
